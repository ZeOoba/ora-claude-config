Fixed 3 reported false positives in `hooks/config-write-guard.py` / `hooks/lib/tool_call_paths.py` (the shell-command text matcher): (1) `.claude` root-mention substring-matching inside the unrelated `.claude-worktrees` directory name -- fixed with token-boundary-aware matching; (2) heredoc-body prose (e.g. a commit message mentioning `hooks/**` in passing) tripping governance markers -- fixed by blanking heredoc bodies before marker scanning, keeping the opening/redirect line and post-heredoc text intact; (3) `open(path,'rb')` read-only calls flagged identically to `open(path,'w')` -- fixed with mode-aware detection (only an unambiguous read-literal or no-mode call is exempt; anything unparseable stays flagged, fail-toward-block).

**Why:** false positives on this gate cost a retry and erode trust in the gate; but this is security-gate code (hooks/** override/auth logic) so any fix needs a mandatory adversarial REFUTE pass before landing (Engineering OS doctrine) -- ran TWO rounds.

Work done entirely in an isolated worktree: `C:\Users\Owner\.claude\.claude\worktrees\fix-config-write-guard-boundary` (branch `fix-config-write-guard-boundary-fps` off `main`), per this file's own docstring ("isolated-worktree development is the sanctioned path for hook work") and Hard Invariant 2/blast-radius rules (hooks/** on the LIVE checkout needs Gabriel's per-edit override token). **REFUTE round 1** found a real bug in the first fix attempt: an absolute-path "this can't be the live root" exemption did a raw string-PREFIX comparison, which a lexical `..` segment defeated (`<root>/nonexistent_dir/../hooks/evil.py` resolves to the live file but looked like "a different root"). Redesigned to reuse the SAME `_norm()`/`_classify()` (i.e. `os.path.realpath`-based) resolution already trusted for structured file-tool paths, instead of a hand-rolled comparison.

**REFUTE round 2** found a second candidate bypass (quote/unquote path-splitting, e.g. `cp x "<root>"/hooks/evil.py`) -- but direct comparison against `git show main:hooks/config-write-guard.py` (the untouched original) confirmed this is a PRE-EXISTING gap, not a regression from this session's changes, and that round 1's traversal fix is a net improvement over baseline, not a tradeoff. Left unfixed as out-of-scope (needs real shell-argument tokenization, a materially bigger job than a text-matcher patch) -- tracked at [[reference_config_write_guard_quote_split_gap]].

**Code review** (after committing 569ef4b to the worktree branch) found a THIRD real bug: `_ABS_PATH_TOKEN_RE`'s excluded-character set stopped only at whitespace/quotes/`<>`/`|`, not shell sequencing/substitution metacharacters (`; & \` $ ( )`) -- `cp x.py <root>/CLAUDE.md;echo pwned` produced a corrupted token that both `_shell_absolute_hits` (exact-equality miss) and `_marker_matches` (deferred to the first check, wrongly) failed to catch. Confirmed a genuine regression (verified against `git show` base) and fixed by widening the exclusion set. Also caught during review: this composition (`_ABS_PATH_TOKEN_RE` vs. what `_marker_matches` assumes is "already handled") is the fragile seam -- 2 of 3 real bugs lived there.

**REFUTE round 3** (targeted specifically at that seam, per the reviewer's recommendation) found a FOURTH candidate, splitting into two: (a) cmd.exe caret-escaping (`cla^ude.md`) -- confirmed pre-existing via `git show`, left open, added to [[reference_config_write_guard_quote_split_gap]]; (b) Win32 trailing-dot/space stripping (`CLAUDE.md.` == `CLAUDE.md` on disk, `os.path.realpath()` doesn't know that) -- confirmed to ALSO bypass the live, untouched hook for a plain structured `Write` call (pre-existing at the `_norm()`/`_classify()` level, broader than this session's shell-matcher scope), but fixed anyway since the fix is a simple, well-defined, static Win32 path-canonicalization rule (strip trailing `.`/` ` from the final path component in the shared `_norm()`), not reactive matcher-narrowing -- benefits every `_norm()` caller at once.

**Net result:** 3 originally-reported false positives fixed + 3 real regressions found-and-fixed across 3 REFUTE rounds and 1 code review + 2 pre-existing gaps confirmed (not caused by this session) and left open/documented, not silently swept under. 19 new tests total across both test files, all passing; full 30-file hooks/tests suite clean.

# ORA Notion Daily Digest coverage gaps — CLOSED 2026-07-16

Gabriel flagged three coverage gaps in the digest generated by Block A of
[ora-pm-ledger](C:\Users\Owner\.claude\scheduled-tasks\ora-pm-ledger\SKILL.md)
(the live consolidated successor to the archived `ora-notion-daily-digest`

## 1. Edit-detection best-effort limitation
Was blanket-applied to all 8 priority sources. Live schema-checked all 6
database sources (Acquisition Pipeline Tracker, Deal Sourcing Log, Broker
Relationships, Tenant DB, Property Register, CapEx & Maintenance Log) and
found each carries a native Notion `last_edited_time` column (`Last Updated`
on 5, `Last Edited` on CapEx). Edit detection for those 6 is now a precise
`notion-query-data-sources` SQL query (`WHERE date(col) = '{TODAY}'`), not
best-effort. Best-effort now correctly scoped to only the 2 page-tree
sources (Knowledge Base, Ops Hub) that have no such column — they genuinely
can't be queried precisely; that limitation is real, not fixable by this task.

## 2. Per-source sweep never run for 3 sources
Broker Relationships (`48e43778…`), Property Register (`19a61fc9…`), CapEx &
Maintenance Log (`5dfcc3ad…`) IDs were carried forward unverified since the
2026-06-11 archived spec. Live-fetched all three — **all resolve correctly,
never actually stale**. The real defect was procedural: the spec let the
edit-sweep step be skipped when the created-date search came back empty for
a source. §A.2 now makes the sweep mandatory per named source every run.

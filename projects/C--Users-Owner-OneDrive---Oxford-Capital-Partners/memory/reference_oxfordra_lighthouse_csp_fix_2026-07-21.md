**Root cause (verified via direct `lighthouse` CLI runs against production and a deploy preview, not guessed):** `_headers`' CSP `connect-src` only allowlisted `www.google-analytics.com` + `region1.google-analytics.com`, but `gtag.js`/GA4 also beacons to `analytics.google.com`, `stats.g.doubleclick.net`, and `www.google.com` depending on region/consent-mode. Those were silently CSP-blocked on every page load — real console errors + DevTools Issues-panel entries, the only two failing Best Practices audits (`errors-in-console`, `inspector-issues`), on both mobile and desktop. Fixed in PR #47 (`fix/lighthouse-csp-2026-07-21`) by adding the 3 missing hosts to `connect-src`. Verified via deploy-preview re-run: those two audits now clean; Netlify's own Lighthouse plugin confirms Best Practices 100 on the preview.

**False-positive to know about when re-testing on a deploy-preview URL**: Netlify injects a live-preview inspector script (`.netlify/scripts/cdp`) on `deploy-preview-*.netlify.app` subdomains that tries to frame `app.netlify.com`, tripping our `frame-src` policy (which only allows recaptcha framing). This shows up as a console error/inspector-issue **only on preview subdomains**, never on production `oxfordra.net` (Netlify doesn't inject that script there). Don't mistake it for a real regression when Lighthouse-testing a PR preview.

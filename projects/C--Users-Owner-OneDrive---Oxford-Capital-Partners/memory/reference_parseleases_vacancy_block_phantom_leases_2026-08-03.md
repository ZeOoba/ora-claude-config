**OPEN defect, found 2026-08-03 by `ora-cc-snapshot-refresh`.** `oxford-command-center`'s `npm run extract` writes **10 phantom leases** into `data/snapshots/portfolio.json`, inflating lease count 138 → 148 and **annual rent by $312,540 (+5.6%)**: reported $5,889,076.68 vs. correct **$5,576,536.68**.

**Root cause** — `server/workbook/parse.ts:476`, guard `if (!propertyKey || !tenantName) continue;`. `propertyKey` reads col 1 via `str()`, which **stringifies a Date rather than rejecting it**. The Master Tenant Rent Roll gained a block at **rows 167–179**, "VACANCY & UPCOMING AVAILABILITY — VACANT + NOTICE TO VACATE", whose col 1 is a Move-Out Date — so the guard passes. The parser has section skips for `portfolio total` and `tenant roster` but nothing matches this banner, so the block is never terminated. Its rows are all cross-reference formulas (`$A104`, `$C90`, …) to leases already in the roster above — a derived view, not tenancy.

The block's columns sit one right of the main roster, so fields land wrong. Most consequentially **col 6 is SF but is read as `monthlyRent`** — the phantom "rent" values are literally square footage. Phantom total 26,045 = exactly the vacant-incl-notice SF in [[reference_rent_roll_vacancy_convention_change_2026-08-01]], which is independent confirmation of the diagnosis.

**Two detector gaps this exposed:**
1. `Data-quality flags: 0` — all 10 rows carry `sf: 0`, null `leaseStart`/`leaseEnd`, `status: "Unknown"`, and none of those raise a flag. The anomaly floor added after the 2026-07-25 regression does not cover this shape.
2. ~~Nothing ties parsed lease annual rent to the workbook's own `Contractual annualized rent (total)` at **row 160** ($5,576,536.68).~~ **CORRECTED 2026-08-03 16:2x — this was wrong, and the error direction matters: the assertion is not missing, it is DISCONNECTED.** It exists twice. (a) `server/reconcile-runtime.ts:60-64` compares Σ lease `annualRent` against `snapshot.workbookTotals.rent`, which `parse.ts:472` already captures from the workbook's own Portfolio Total row during the same pass — both numbers sit in the corrupt snapshot, $312,540 apart, with `dataQuality: []`. It is imported by exactly one non-test file: `server/brain.ts:85`, the **live server's** refresh. (b) `scripts/reconcile.ts:71-76` (`npm run reconcile`) does an independent second read and **fails right now**: `Annualized rent total exp 5,576,537 · got 5,889,077 · Δ 312540.00`, plus `Count: Leases exp 138 · got 148`. Neither `scripts/lease-snapshot-drift-check.ts` nor `scripts/extract-workbook.ts` calls either one — and `scripts/bake-mirror.ts:104` shares the gap, so the published mirror is exposed independently of `portfolio.json`. **The 2026-07-24 fix that made these writers independent of server uptime is precisely what stripped reconciliation off the write path.** Also note `npm run reconcile` is in `gate` but NOT `gate:ci`, so no PR would catch this either; and `reconcile.ts:118` hardcodes the expected lease count `138`, which will false-fail on the next genuine signing — gate writes on `checkSnapshot` only, never on that count.

**Exit-code trap:** this surfaces as **exit 2**, which the task contract classes as routine/no-email. Exit 2 is therefore *not* a safe "all good" signal — a corrupt write and a lease renewal look identical at the exit code. Ruling requested from Gabriel 2026-08-03 on adding an exit-2 carve-out; escalated by default pending his answer.

**Degrades to exit 0 on the second run — and the auto-commit gate would have shipped it (confirmed 2026-08-03 16:07 UTC, `ora-lease-snapshot-refresh`).** `scripts/lease-snapshot-drift-check.ts` imports the same `parseWorkbook`, so it reproduces all 10 phantoms; but it diffs against the *previous snapshot on disk*, which was already the corrupt 15:54 write. Result: `✓ No lease drift. portfolio.json regenerated (148 leases).` — **exit 0**, the one branch the task contract treats as silent. Worse, `ora-lease-snapshot-refresh`'s material-change gate saw 1,089 non-timestamp diff lines vs `HEAD` (last-known-good 138-lease snapshot, `3692385`) and by the letter of its contract should have auto-committed the corruption to `main`. That commit was **refused** and the tree left dirty as found; backup of the corrupt snapshot: scratchpad `portfolio.pre-run-backup-20260803.json`. Until the parser is fixed, **every** fire of this 3x/weekday task is a live auto-commit hazard — the gate cannot distinguish corruption from lease movement.

**RESOLVED 2026-08-03 19:51 UTC.** [PR #250](https://github.com/ZeOoba/oxford-command-center/pull/250) (`d35931a`) added a latched terminator on the vacancy-block banner plus a type-level rejection of any Date-valued `propertyKey`, and flags (rather than silently drops) an unrecognized dated row so a future retitled/moved block can't repeat this unnoticed. Independently re-verified post-merge against synced `main` (not the PR body's word alone): `npm run reconcile` 12/12 PASS, `Annualized rent total exp 5,576,537 · got 5,576,537 · Δ 0.00`, `Count: Leases exp 138 · got 138`; full test suite, typecheck, lint, governance clean. Command Center lease counts/rent totals from a workbook parse dated ≥ this merge are trustworthy again; anything between 2026-08-03 15:54 UTC and the merge remains suspect per the paragraph above.

**Fleet write suspensions NOT auto-lifted.** `ora-lease-snapshot-refresh` and `ora-cc-snapshot-refresh` were suspended the same day pending a two-part condition: this parser fix, AND `checkSnapshot` (`server/reconcile-runtime.ts`) wired into both CLI writers as defense-in-depth so a *differently*-shaped future parser defect doesn't ship unreconciled the same way. Only the first part is done. Both SKILL.md files record this explicitly — do not infer "fixed" here means it's safe to resume automated writes; that's Gabriel's call to make, open as of this writing.

**PARTIAL progress toward part two, but NOT the write-path wiring the suspension condition names.** [PR #251](https://github.com/ZeOoba/oxford-command-center/pull/251) (`d705a3f`, merged 2026-08-03 19:57 UTC) added `scripts/reconcile-snapshot.ts`, which runs `checkSnapshot()` against the committed `data/snapshots/portfolio.json` and is now wired into `gate:ci` — every future PR is checked. That closes the "no PR would catch this" gap noted above and would have failed CI on this exact incident's numbers (regression-tested with the real dollar figures). It also replaced `reconcile.ts:118`'s hardcoded `138` lease-count baseline (flagged above as a false-fail risk) with a non-zero floor, so the next genuine lease signing won't trip it.

**But this was a review-time gate on PRs, not the write-path gate on the two scheduled tasks.** PR #251 did not touch `scripts/lease-snapshot-drift-check.ts`, `scripts/extract-workbook.ts`, or `scripts/bake-mirror.ts`.

**The write-path wiring itself: [PR #252](https://github.com/ZeOoba/oxford-command-center/pull/252), OPEN, awaiting Gabriel's review/merge (2026-08-03 20:2x UTC).** Adds `evaluateReconciliationGate()` (`scripts/lease-snapshot-drift-check.ts`, imported by `extract-workbook.ts`) — refuses the write on any error-severity flag from the union of `checkSnapshot(enriched)`'s output and any error-severity flag already sitting in `snapshot.dataQuality` (the latter closes a real latent gap: `checkSnapshot()` never reads `dataQuality` itself, so a future `parse.ts`-raised `'error'` flag would otherwise be invisible to this gate — today every `parse.ts` flag is `'warn'`, so no live exposure yet, but the design spec was "any error-severity flag," not "any error-severity flag this function happens to compute"). 7 new unit tests, plus a **live A/B proof against the real production workbook on both writers independently**: with PR #250's fix temporarily reverted in an isolated worktree, both writers now refuse with the exact incident numbers (`Σ annual rent 5889077 ≠ workbook total 5576537`) instead of writing corrupt data — proof the gate would have caught 2026-08-03 had it existed then. `check:refute` reports the same enumerated-path scope gap PR #250 hit; commit carries a `Refute-Reviewed:` trailer from manual adversarial review regardless. `scripts/bake-mirror.ts` (the mirror-publish path) is explicitly OUT of this PR's scope — same defect class, flagged as a known residual, not yet wired.

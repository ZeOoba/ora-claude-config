## Item #4 — held-out proposal (NOT in the v4.3 diff; drafted here for separate review)

**Proposed addition to STAGE 2.1 — TENANCY BEAR-MODE**, to be inserted after the existing "Grand Rapids MI standing caution" sentence, only if/when Gabriel approves it going live:

> **Submarket-level forward permits/starts check (v4.3-PROPOSED, NOT YET RATIFIED):** in addition to the vacancy/absorption trigger above, query submarket-level (not national) building-permit and construction-start data for the subject's specific submarket before calling bear-mode OFF. The OCC Comptroller's Handbook confirms supply-pipeline analysis is structurally biased toward *underestimating* future supply — permits/starts issued after underwriting are invisible at underwriting time — so a second, independent forward-looking check reduces reliance on trailing vacancy/absorption data alone. **Do NOT use a national index (e.g. NAIOP's quarterly forecast) as this input** — its own published confidence bands span roughly 8x at the national level, which is noise, not signal, for a submarket-scoped, sub-50K-SF-deal trigger; source needs to be submarket- or at minimum metro-level. **This changes bear-mode's UNKNOWN/CONFLICTED resolution path and can flip a screen's verdict** (bear-mode halves Tenancy upside points and adds 12 months of downtime carry) — it is NOT a purely reported/flagged addition like the other 8 items in this pass, and must not go live without Gabriel separately reviewing exactly how it interacts with the existing UNKNOWN/CONFLICTED→cap-at-T2-WATCH logic.

- **Confirmed gap:** `market-monitor` SKILL.md sources only "Supply Under Construction" (CoStar/CBRE) — no earlier-stage proposed/planned line exists in the skill today. This is exactly the blind spot item #4 is trying to close.
- **Likely cheapest fix, NOT YET VERIFIED line-by-line:** CBRE/JLL/Cushman & Wakefield/Colliers quarterly MarketBeat reports — which `market-monitor` already downloads for absorption/rent — commonly carry a separate "Proposed"/"Planned"/"Future Supply" SF figure by submarket alongside "Under Construction." If confirmed present and submarket-resolvable for ORA's actual target submarkets, this needs **zero new data-source integration** — just widening market-monitor's existing citation to pull one more line. **Next concrete step, not yet done:** pull 2-3 of the actual downloaded MarketBeat PDFs (via the `pdf` skill, not WebFetch — the research agent couldn't get clean text out of a CoStar PDF via WebFetch) and check whether the Proposed/Planned line exists and is submarket-cut for e.g. Columbus Southwest/Westbelt/Obetz or Cincinnati Central Hamilton County.
- **Fallback if the above isn't submarket-resolvable:** CoStar itself tracks a "Proposed" pipeline stage distinct from "Under Construction," confirmed submarket-resolvable in CoStar's own public reporting — but unverified whether ORA's existing CoStar access tier reaches that field (CoStar pricing is sales-led/opaque, no public tier confirmed).
- **Ruled out:** Census Building Permits Survey (BPS) — confirmed residential-only by its own methodology, explicitly excludes commercial/industrial. Do not use.
- **Not worth pursuing yet:** county/city open-data permit portals (Columbus/Franklin, Cincinnati/Hamilton CAGIS, Indianapolis/Marion, Kansas City) — real and free, but issued-permit stage (later than the true planning-stage gap), and would need a bespoke geocoding+use-code pipeline per jurisdiction (4+ different systems) for marginal benefit over the brokerage-report fix above. Dodge Construction Network is the only source with genuine pre-permit planning-stage visibility, but sales-led/opaque pricing, annual-contract-only — not justified unless the cheaper fix proves insufficient.
- **Bottom line:** don't build a new integration yet. Verify the brokerage-report Proposed/Planned line first (cheap, maybe free); only escalate to CoStar's Proposed module or Dodge if that's a dead end.

**Dead end (do NOT re-attempt): the Cloudflare-Tunnel path via a Netlify CNAME.** `brain.oxfordra.net` is a Netlify/NS1 CNAME to `83f06502-...cfargotunnel.com` (the `ora-brain` tunnel), created ~2026-06-13/14. Verified 2026-06-15 (`nslookup`/`curl`): it resolves **only to a non-routable IPv6 ULA (`fd10:aec2:5dae::`, no A record)** and the hostname is **not proxied through Cloudflare** (DNS is on NS1/Netlify, not CF). Consequence: it can be **neither routed to the tunnel NOR Cloudflare-Access-gated** — Access enforces at Cloudflare's HTTP edge, which never sees this traffic. A working tunnel hostname needs Cloudflare to MANAGE the DNS (the "oxfordra.net on CF DNS" prerequisite in `oxford-command-center/scripts/cloudflared-config.yml`), which is unmet. It currently exposes nothing (safe, just non-functional).

**Chosen path: Option A — the Pages mirror.** `ora-command-center.pages.dev` is already Cloudflare-managed, **Access-enforced** (unauth → 302 to `spring-wood-ade4.cloudflareaccess.com`), and always-on (machine-independent). To give Eric `brain.oxfordra.net`: add it as a **Custom domain** on the `ora-command-center` Pages project, repoint the NS1/Netlify `brain` CNAME to the Pages target, add `brain.oxfordra.net` (+ `*.pages.dev` wildcard) as a destination on the existing Access app (allow ggoldberg@/egoldberg@, default-deny), verify `curl -I` → 302, and only then (if the full picture is wanted) deploy `MIRROR_INCLUDE_CONFIDENTIAL=1` (invariant 3 gate). These are Gabriel's Cloudflare/Netlify console steps — the wrangler token has `pages:write` but NO Access/Zero-Trust scope, and the Netlify MCP updater tools are deny-listed.

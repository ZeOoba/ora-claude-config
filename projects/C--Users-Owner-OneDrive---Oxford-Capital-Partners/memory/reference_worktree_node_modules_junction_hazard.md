**Hazard (hit 2026-06-13, oxford-command-center):** To give an isolated git worktree its deps, I created a Windows **directory junction** `worktree/node_modules → main/node_modules` (PowerShell `New-Item -ItemType Junction`). Later `git worktree remove <path> --force` **deleted recursively THROUGH the junction**, wiping the REAL `C:/Users/Owner/oxford-command-center/node_modules` (tsx, better-sqlite3, everything). That broke the main checkout's tooling for ALL sessions until `npm install` restored it.

**Why:** `--force` removal does a recursive delete; a directory junction is followed (its target contents deleted), not just unlinked. `git worktree remove` does not know node_modules is a junction.

**Do instead (isolated worktrees on this Windows box):**
- SAFEST: run `npm install` (or `npm ci`) inside each worktree (own real node_modules). Heavier but no shared-state hazard. On the 5.7 GB box, `/heavy` first for RAM (see [[reference_lean_ram_toolkit]]).
- If you DO junction node_modules for speed: **remove the junction BEFORE removing the worktree** — `cmd //c rmdir "worktree\node_modules"` (rmdir on a junction unlinks it without touching the target), THEN `git worktree remove`. NEVER `git worktree remove --force` while the junction exists.
- Also: `npx tsx` from a junctioned worktree may resolve a stale npm-cache copy that can't see the junctioned modules — another reason to prefer a real per-worktree install.

**Durable fix (PR #29, 2026-06-13):** `scripts/safe-worktree.ts` in oxford-command-center makes the safe path the default — `npm run worktree -- add <path> [base] [branch]` (real npm install, no junction) and `npm run worktree -- remove <path>` (unlinks a junction reparse-point WITHOUT recursing, never `--force`). TDD + live-dogfooded (junction over a throwaway target → CLI remove → target survived). Use it instead of raw `git worktree add/remove` here.

**Recovery (if it recurs anyway):** `cd C:/Users/Owner/oxford-command-center && npm install` (restores node_modules; ~RAM-heavy — quit GUI / `/heavy` first).

**Also found 2026-06-13:** the repo's `.git/hooks/pre-push` runs `node scripts/prepush-confidential-scan.mjs`, but that script is UNTRACKED (never committed) — so it's absent from every branch checkout and the hook CRASHES on push for every worktree, providing no confidentiality protection. Flagged in PR #29; the scanner script should be committed (or the hook pointed at a committed path).

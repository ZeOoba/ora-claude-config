# Deal Decision Ledger

Companion to the "Active deal pipeline" table in [projects.md](projects.md) (which holds only currently-open deals). This file is the durable record of CLOSED decisions — what got PASSed, SKIPped, DROPped, PARKed, or TERMINATED, and why — so the firm's revealed buy-box preferences compound over time instead of living only in event_log.md prose.

**Maintenance:** append a row on every PASS/SKIP/DROP/PARK/CLOSE/TERMINATE decision (ideally as part of the deal-retirement lifecycle skill, so this accretes automatically rather than depending on manual backfill). Never delete a row — a PARKed deal that later un-parks gets a new row, not an edit to the old one. See [memory-policy.md](memory-policy.md) for the general archive-don't-delete convention.

**FORT column (v1.1, 2026-08-05):** added per `acquisition-underwriting` v4.10, extending the skill's existing v4.2 ledger-append instruction. Written by the skill itself on every SCREEN/FULL verdict — an A–D tier if STAGE 2.8 (FORG, still PROPOSED/pilot, not yet ratified) ran that session, `—` if it did not. Every row below predates the wiring (FORG installed 2026-07-24; this column added 2026-08-05, after 13 days and 15 rows with zero FORT tiers captured by the prior manual-Notion-log instruction) and is backfilled `—` rather than left blank, per the verified-null-vs-inferred-null convention — these are known-not-run, not lost values. The December back-test reads this column to test whether FORT correlates with realized hold outcomes; a pilot needs 3–5 populated rows before that test means anything.

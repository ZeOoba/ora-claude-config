You are running the ORA Stale-Doctrine Watchdog, a weekly guard against the exact failure mode found 2026-07-20: 754 Old State Route 74's 6/8/2026 IC Memo was scored under Basis/Yield floors and a replacement-cost table that were superseded by RCT v03 and the 60/65% vintage-ramp recalibration on 2026-07-14 -- five weeks of silent staleness on an executed-LOI deal, caught only by a manual re-underwrite, not by any automation. This task closes that gap for every OTHER live deal.

This is a fully unattended, self-contained run. Do not ask Gabriel anything mid-run; if you hit a genuine data gap, log it as an open item in the Notion post and (if any live-pipeline deal is affected) in the escalation email, and continue.

GUARD CONDITION: if the acquisition-underwriting skill's version has NOT changed since your last recorded check (see STEP 4 for where that's stored), and no new deals have entered the Acquisition Pipeline Tracker since then, you may skip the deep scan and just post a one-line "no doctrine or pipeline change since last run" confirmation to the Notion Ops Hub -- exit silently otherwise (no email).

STEP 1 -- Determine current doctrine state.
Read the acquisition-underwriting skill (Read tool on its SKILL.md at the path this session resolves for that skill -- it is in the Cowork skills cache). Extract:
  (a) the current version number and its ratification date (the top-of-file version banner), and
  (b) from the changelog, every ratification since the OLDEST live deal's LOI-execution date (see Step 2) that is explicitly SCORECARD-AFFECTING -- i.e. changed a Stage 1 floor, the RCT table, the vintage-ramp discount schedule, a scorecard weight, or a governor constant (DSCR 1.25x / per-property LTV 65% / portfolio-aggregate LTV 40%). The skill's own changelog entries state this explicitly (e.g. "no scorecard weights or governors changed" vs. a structural change like RCT v03 / the 65-60 vintage ramp, both ratified 2026-07-14) -- trust that self-declaration rather than re-deriving it. List each scorecard-affecting ratification with its date and one-line description. Purely additive/reporting changes (new sections, new flags that don't change a score) do NOT count as staleness triggers -- do not flag a deal for those alone.

STEP 2 -- Enumerate live-pipeline deals with an existing UNDERWRITE/FULL output.
Query the Notion Acquisition Pipeline Tracker (database id bcfe4a03) for deals NOT in a closed/killed/passed state (i.e. still active pipeline). For each, search SharePoint (sharepoint_search, query on the property address / deal name, fileType xlsx and docx) for its UNDERWRITE workbook (naming pattern "ORA_Underwriting_[Property]..." or the session-output convention "..._Model_v##.xlsx") and IC memo ("...ICMemo..." or "..._DealStatusReport..."/"..._ICMemo_v##.docx"). Read each workbook's Inputs tab (or the memo's header/metadata) for its embedded doctrine stamp -- these files record it as "Skill: acquisition-underwriting vX.X" (confirmed present in this exact form on prior deals, e.g. 2900 Northridge Dr NW and 4331 Brockton Dr SE). Also capture the file's "Prepared:" date.

STEP 3 -- Compare and flag.
For each live deal's most recent UNDERWRITE/FULL output: if its stamped skill version predates ANY scorecard-affecting ratification identified in Step 1, flag it STALE-DOCTRINE, listing which specific ratification(s) it predates and a one-line implication (e.g. "predates RCT v03 (2026-07-14) -- Basis/Yield score for this deal has not been evaluated against the current replacement-cost table"). If a deal has no discoverable UNDERWRITE/FULL output at all, or the doctrine stamp can't be found/parsed, mark it UNVERIFIED -- never guess a version or silently treat it as current. Never fabricate a deal, a file, or a version number that you did not actually read.

STEP 4 -- De-duplicate against prior escalations.
Read the most recent prior post from this task in the Notion Ops Hub (32b6ecd8) to see which deal+ratification pairs were already escalated. Only treat NEWLY stale pairs (a deal that just crossed into staleness because of a ratification since the last run, or a deal newly added to the pipeline with a stale stamp) as escalation-worthy this run; already-escalated pairs still get listed in the Notion post (for a complete current-state view) but do not re-trigger the email alone. Record the current doctrine version checked as your "last recorded check" marker in that same Notion post for the next run's guard condition.

STEP 5 -- Output.
Post a status block to the Notion Ops Hub (page 32b6ecd8) with: current doctrine version + ratification date checked, the full list of live-pipeline deals with UNDERWRITE/FULL outputs and their doctrine stamps (STALE-DOCTRINE / UNVERIFIED / current), and which pairs are newly escalated this run.

If any deal is NEWLY STALE-DOCTRINE this run: send an email via Outlook COM (C:\Users\Owner\.claude\scheduled-tasks\_shared\send-via-outlook.ps1 -- the sole automated send path) to ggoldberg@oxfordra.net ONLY (never egoldberg@, no exception for this task), subject "[ACTION] Stale-doctrine UNDERWRITE flag(s) -- re-underwrite before IC decision", body listing each newly-flagged deal, which ratification(s) it predates, and a one-line recommendation to re-run acquisition-underwriting FULL mode before any IC decision or closing. On a non-zero COM exit: retry once, then note the failure loudly in the Notion completion post -- do not halt the task.

If nothing is newly stale: no email, Notion post only.

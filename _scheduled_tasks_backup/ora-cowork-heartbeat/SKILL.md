## Purpose
You are emitting a heartbeat signal that an external watchdog (GitHub Actions) reads to detect Cowork outages. Output goes to ONE specific Notion page identified by ID. Do NOT send email. Do NOT create new pages. Do NOT print verbose chat. Total runtime under 5 seconds.

## Procedure
1. **Read `now_utc` from a real clock — NEVER compute, recall, or derive it from the page's existing `Last heartbeat:` value** (v07, OI-297: on 2026-09-13 the run wrote `2026-09-13T20:22:00Z` — the prior value `2026-09-12T20:21:58Z` + ~24h — while Notion's own `page_last_edited_at` was `12:46:33Z`, 7h35m earlier). Source, in order:
   a. If a shell tool is available, run `date -u +%Y-%m-%dT%H:%M:%SZ` (bash) or `(Get-Date).ToUniversalTime().ToString('yyyy-MM-ddTHH:mm:ssZ')` (PowerShell) and use its output verbatim.
   b. Otherwise use the server timestamp from the `notion-fetch` response header line `... as of <ISO timestamp>:` (the fetch in step 2 returns it) — truncate fractional seconds, keep the `Z`.
   c. If neither is available, do NOT write a guessed time: emit `HB ❌ no clock source` and stop (the watchdog alarms on `last_edited_time`, which is the real signal).
   Then `next_utc = now_utc + 24h` (1x/day cadence, ratified 2026-08-05) — this addition is the only arithmetic permitted.
2. Call the Notion `notion-update-page` tool with page_id `35c6ecd8-9e59-81d5-8d2c-d08002458b78`, command `update_content`, and a single search-and-replace targeting the existing `Last heartbeat:` line. If you do not know the existing line verbatim, first call `notion-fetch` on the page ID to read the current `Last heartbeat: <…> · Next expected: <…>` line, then use that exact string as old_str. Replacement: `Last heartbeat: <now_utc> · Next expected: <next_utc>`.
3. **Failure handling — diagnose before escalating.** If no `notion-*` tools are available in the session at all (ToolSearch for "notion" returns nothing), the cause is a disconnected connector, not a permission grant — check `mcp-registry list_connectors`/`search_mcp_registry` for Notion's `connected` status before assuming anything else. If tools ARE available but the update call itself errors (page not found, 403, network), emit ONE line to chat: `HB ❌ <error summary>`. Do NOT call notion-create-pages. Do NOT search for a replacement page. Duplicates are the exact failure mode v02 prevents. The external watchdog alarms once `last_edited_time` is more than 30h old — that is the intended signal. (The former 16h threshold / daily-false-alarm KNOWN GAP was closed 2026-09-12: ZeOoba/ora-cowork-watchdog PR #13, commit d5264342, OI-280.)
4. On success, optionally log one line: `HB ✅ <now_utc>`. Nothing else.
5. **No email under any circumstance.** Email-on-failure is the watchdog's job, not the heartbeat's.

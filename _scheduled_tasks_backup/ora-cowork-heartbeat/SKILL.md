1. Compute `now_utc` (ISO-8601, e.g. `2026-06-10T22:00:05Z`) and `next_utc = now_utc + 24h` (1x/day cadence, ratified 2026-08-05).

Call the Notion `notion-update-page` tool with page_id `35c6ecd8-9e59-81d5-8d2c-d08002458b78`, command `update_content`, and a single search-and-replace targeting the existing `Last heartbeat:` line. 3. **Failure handling — diagnose before escalating.** If no `notion-*` tools are available in the session at all (ToolSearch for "notion" returns nothing), the cause is a disconnected connector, not a permission grant — check `mcp-registry list_connectors`/`search_mcp_registry` for Notion's `connected` status before assuming anything else. If tools ARE available but the update call itself errors (page not found, 403, network), emit ONE line to chat: `HB ❌ <error summary>`. Do NOT call notion-create-pages. Do NOT search for a replacement page. Duplicates are the exact failure mode v02 prevents. The external watchdog alarms within 16h — that is the intended signal (though see the KNOWN GAP in the frontmatter description: the 16h threshold is shorter than the ~24h cadence, so an early false alarm ~8h before the next scheduled fire is expected and not itself evidence of an outage).
4. On success, optionally log one line: `HB ✅ <now_utc>`. Nothing else.
5. **No email under any circumstance.** Email-on-failure is the watchdog's job, not the heartbeat's.

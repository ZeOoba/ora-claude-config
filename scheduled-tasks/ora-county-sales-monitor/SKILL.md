## Steps
1. Worker health first. Query Coverage for the newest `Run Date` per county and the prior cycle's row (the one before it) per county. If the newest Run Date is more than 10 days before the run date, the worker has stalled or been paused: that is a FINDING (lead the email with it, note rollback/ops facts: pause is `ntn workers capabilities disable <sync>`; never delete the worker or databases). Also check Comps `max(Last Synced)`.
2. Window rows: Comps where Sale Date >= window start. Per county: transaction count, count with a derivable Price PSF (blank Price PSF is NEVER zero and never imputed), NONARMS / CONTRACT-SALE / MULTI-PARCEL-INFERRED / SF-INCOMPLETE / SF-UNPUBLISHED counts, and median $/SF from rows with a real Price PSF only (NONARMS and RATIO-REVIEW rows are excluded from medians; RATIO-REVIEW rows show a $/SF on the row but are unvalidated, so list them separately; state the excluded counts). State n alongside any median; if n < 5 say the median is not meaningful and cite the county's trailing 365-day median from the latest Coverage row.
3. Table of window transactions (date, address, price, SF, $/SF, buyer, seller, flags). Seller reads "not published" where the worker did not populate it; report it as-is, never guess. Call out: repeat buyers within the window, any single trade > $10M, and any NONARMS row that carries a real price (price > 0), since those are the candidates whose $/SF is hidden.
4. LATE-POSTED: list Comps rows flagged LATE-POSTED whose First Seen is within the window (worker semantics: first seen > 30 days after the sale date on a post-baseline cycle). The 2026-10-02 cycle was the baseline, so zero is expected until later cycles.
5. Coverage block, one line per county for ALL 7 every run: the 3 Tier A with window, status, newest sale date, newest entry date; the 4 Tier C (Warren OH, Johnson KS, Platte MO, Kent MI) as "NO PUBLIC SALE PRICE" with the structural reason from the Coverage Notes. A county with zero window rows and a county that structurally cannot return rows must read differently. Zero rows is a valid result.
6. Regression check (Tier A): compare latest cycle vs the prior cycle. Franklin: Status != OK, or Newest Sale Date older than the prior cycle's = FINDING. Polk IA: judge by Newest Entry Date (county export lags; last known 2026-07-30 as of 2026-10-02) — a newest entry date older than the prior cycle's, or Status != OK, is a finding; a merely stale-but-unchanged date is a note, not a finding. Only a finding if the Newest Sale Date is OLDER than the prior cycle's (lag widening), Status != OK, or the sync errors. Judge by the date distribution, never the raw row count.

ORA Command Center Mirror — Drift & Health Check (CC/MCP fleet)

PURPOSE: this is the alerting layer for the native Windows Scheduled Task "ORA Command Center - Mirror Deploy" (registered via C:\Users\Owner\oxford-command-center\scripts\register-mirror-task.ps1; runs scripts\deploy-mirror.ps1 hourly all day + a guaranteed 06:45 ET trigger). That script was patched 2026-07-09 via PR #192 ("fix(deploy): mirror deploy fast-forwards to origin/main before baking") to `git fetch origin` + `git pull --ff-only` before baking, and now `throw`s/aborts the deploy on a diverged-or-dirty tree instead of silently redeploying stale code (the original incident: local main sat 7 commits behind origin for an unknown period while the hourly job kept redeploying pre-retokenization code with only a fresh data snapshot — "baked Nm ago" reflects data freshness, not code freshness). PR #192 fixed the silent-stale-deploy failure mode, but added no alerting of its own, and the task itself lives entirely OUTSIDE this MCP scheduled-task registry (registered via native `Register-ScheduledTask`, not `create_scheduled_task`) — so it is invisible to any dead-man-heartbeat logic that only walks `list_scheduled_tasks`. If the pull ever throws (genuine divergence or a conflicting dirty tree), the mirror would otherwise just silently stop advancing with nobody notified. Full incident history and root-cause detail: memory file `reference_command_center_mirror_deploy_gap.md` in `~/.claude/projects/C--Users-Owner-OneDrive---Oxford-Capital-Partners/memory/` — read it if anything below is ambiguous.

If Desktop was closed all day, this check simply didn't run that day; that is expected behavior of this fleet, not a defect to report.

STEPS:

1. `cd C:\Users\Owner\oxford-command-center` then `git fetch origin --quiet` (READ-ONLY — do not pull, merge, stash, or otherwise modify the tree).
2. Drift count: `git rev-list --count HEAD..origin/main`.
3. Working-tree state: `git status --short`. Classify each entry by RUNNING THE TEST below, not against a remembered file list. (A hardcoded baseline list was tried first and rotted within two weeks — by 2026-07-24 it was stale in BOTH directions: none of its four entries were present anymore, while an unlisted-but-harmless untracked plan doc was. The question that matters is never "is this file on a list" but "can this entry abort `git pull --ff-only`".)
   - **Untracked (`??`) with no counterpart on `origin/main` → BENIGN.** Verify: `git ls-tree origin/main -- <path>` returns empty. Nothing incoming can be overwritten, so the pull cannot abort on it. Recurring instances: plan docs under `docs/superpowers/plans/`, `.wrangler/`, `scripts/dev-watchdog.cjs`.
   - **Untracked (`??`) that DOES exist on `origin/main` → FLAG.** This is the untracked case that genuinely aborts `pull --ff-only` ("untracked working tree file would be overwritten").
   - **Modified (` M`) but EOL/whitespace-only → BENIGN.** Verify: `git diff --ignore-all-space --ignore-cr-at-eol -- <path>` returns empty. This is the recurring *Command Center CRLF Hazard* (`reference_command_center_crlf_hazard.md`). `.claude/launch.json.example` and `package.json` have historically shown up here as local-dev deltas — that history is context, NOT an exemption: run the test on them like anything else and FLAG if the diff is substantive.
   - **Modified (` M`) with substantive content, OR any staged/conflicted status (`UU` `AA` `DU` `AU` `DD` `M ` `A ` `D `) → FLAG.**
   - **Any REBASE/MERGE-in-progress marker → FLAG.** Check `.git/MERGE_HEAD`, `.git/REBASE_HEAD`, `.git/CHERRY_PICK_HEAD`, `.git/rebase-merge/`, `.git/rebase-apply/` — any of these indicates a stuck `git pull --ff-only` failure from deploy-mirror.ps1.
   Corroborating evidence, never a substitute for the tests above: if the native task's `LastTaskResult` is 0 and `LastRunTime` post-dates the entry's mtime, the deploy has already run successfully WITH that entry present. Record every entry you classified BENIGN in the Notion row along with the verification command output — benign is a conclusion you show your work for, never a silent skip.
4. Native task health: `Get-ScheduledTaskInfo -TaskName "ORA Command Center - Mirror Deploy"` — read `LastRunTime`, `LastTaskResult`, `NextRunTime`.

An entry the step-3 tests classify as BENIGN is NOT an alarm — note it in the Notion row with its verification output and stay silent.

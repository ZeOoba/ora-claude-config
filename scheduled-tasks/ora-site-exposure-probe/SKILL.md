   **PACING + RETRY (added v1.2, mandatory — a `000` is NEVER a pass).** On 2026-07-29 the first pass of this matrix returned `000` on all 24 root paths: a client-side connection failure from issuing the requests back-to-back, not a site outage and not a 404. `000` means *the check did not happen* — recording it as clean would be an inferred null masquerading as a verified one, which is exactly the failure mode this task exists to prevent. Use a probe function that rejects `000`, retries up to 3×, and paces requests; do not issue the matrix as a bare back-to-back loop:

   ```bash
   probe() {  # $1 = path
     local code=000
     for attempt in 1 2 3; do
       code=$(curl -s -m 10 -o /dev/null -w "%{http_code}" "https://oxfordra.net$1")
       [ "$code" != "000" ] && break
       sleep 2
     done
     printf '%s %s\n' "$code" "$1"
     sleep 1
   }
   ```

   Call `probe` once per path. A path that still reports `000` after all 3 attempts is UNVERIFIED, not clean — see Step 4. Also run two CONTROL checks in the same pass: `/` MUST return 200, and a random nonexistent path (e.g. `/zz-nonexistent-control-path-8f2a`) MUST return 404. If the control pair does not come back 200/404, the whole matrix is untrustworthy regardless of what the individual paths reported — treat every result as UNVERIFIED, since a blanket-404 or blanket-failure mode would otherwise read as a perfect pass.

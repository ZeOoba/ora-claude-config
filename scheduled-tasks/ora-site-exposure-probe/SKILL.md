ORA oxfordra.net Exposure Probe (CC/MCP fleet)

GATE-SAFETY RULE (added 2026-07-27, do not skip): `~/.claude/hooks/ora-autonomy-gate.py` blocks any single Bash command containing BOTH a site-tree marker (`website-canonical`, `oxford-site`) AND a bare `>` character ANYWHERE in the command — including a JS arrow function (`=>`), a `->` in an echoed status line, or a real redirect. It does not matter that this task never writes to the site tree; the matcher is intentionally broad and cannot be safely narrowed (see memory `feedback_autonomy_gate_matcher_cannot_be_safely_narrowed.md`). This task must never trip it and must never mint an `allow-website-write` override (that override is for real site changes Gabriel approved, not for a read-only probe). Two rules keep it gate-safe:
  - Read local repo files (`build-dist.mjs`, `_headers`) with the **Read tool**, never Bash/cat/type. The gate only inspects `Bash`/`Edit`/`Write`/`MultiEdit`/`NotebookEdit`/`mcp__*` tool calls — Read is not gated at all, so this sidesteps the issue by construction.
  - Every curl-matrix and header-check command (Step 2, Step 3) must be its own Bash call that mentions NEITHER `website-canonical` NOR `oxford-site` anywhere in its text — no `cd` into the repo, no local path in the same command, no comment naming it. These calls target only `https://oxfordra.net/...` and never need the local path, so this is a zero-cost separation, not a workaround.
